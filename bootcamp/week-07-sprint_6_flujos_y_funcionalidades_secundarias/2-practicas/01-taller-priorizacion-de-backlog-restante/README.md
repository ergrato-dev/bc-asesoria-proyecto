# Taller — Priorización del Backlog Restante

<!-- 📝 Instrucción: taller guiado por el instructor, en equipo, con el backlog real del proyecto
     a la vista en GitHub Projects. Es el Sprint Planning breve de esta semana. -->

## Objetivo

Salir de este taller con el Sprint 6 definido: las historias restantes del backlog revisadas,
priorizadas con criterio y movidas a `Sprint Actual`, cada una viable como vertical slice esta
semana.

## Duración estimada

30-45 minutos (dentro del bloque de Ambiente de Formación de 6h).

## Pasos

### 1. Revisar el backlog restante (10 min)

- [ ] Abrir el GitHub Project del proyecto real
- [ ] Confirmar que todas las historias pendientes del informe de diseño están cargadas como Issues (nada fuera del tablero)
- [ ] Marcar cuáles ya tienen dependencias resueltas por sprints anteriores (2-6) y cuáles no

### 2. Priorizar con la matriz impacto/esfuerzo (10 min)

- [ ] Ubicar cada historia restante en la matriz de `1-teoria/01-priorizacion-backlog-y-vertical-slice.md`
- [ ] Discutir en equipo solo las historias donde haya desacuerdo — no cada una desde cero

### 3. Decidir qué entra al Sprint 6 y qué se recorta (10 min)

- [ ] Mover a `Sprint Actual` solo las historias que caben completas esta semana
- [ ] Documentar el motivo del recorte en un comentario del issue de cada historia que queda fuera
- [ ] Crear el Milestone `Sprint 6 — Flujos y funcionalidades secundarias` si no existe, y asignarlo a las historias que entran

### 4. Verificación de vertical slice (10-15 min)

- [ ] Para cada historia que entra al sprint: confirmar que un integrante puede completarla de
      punta a punta (persistencia + lógica + endpoint + consumo en frontend, según aplique) dentro
      del Trabajo Autónomo de esta semana
- [ ] Si una historia no cabe completa como vertical slice, partirla en sub-tareas o devolverla al backlog

## Cierre del taller

Al terminar, el tablero de GitHub Projects refleja el Sprint 6 real: historias priorizadas,
viables como vertical slice, y el resto del backlog con su recorte documentado. El equipo pasa
directo a codificar en `3-proyecto/`.
