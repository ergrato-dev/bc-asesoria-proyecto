# Proyecto Semana 1 — Plan de Trabajo y Sprint 0

## 📋 Instrucciones

Con el entorno ya configurado (`2-practicas/01-taller-configuracion-entorno/`), este entregable
cierra dos cosas:

1. El **plan de trabajo** (Criterio RAP-1): documento formal que traduce el informe de diseño en
   backlog priorizado y stack decidido.
2. El **Sprint 0**: primer código real del proyecto, mergeado a `develop` pasando CI.

Completa `starter/entregable-s01-plan-de-trabajo.md` con tu equipo.

## ❓ Preguntas Guía

- ¿Qué historias de usuario del informe de diseño son "core" y cuáles pueden esperar a sprints posteriores?
- ¿Qué entidad de dominio tiene menos dependencias y por eso es el mejor punto de partida para el Sprint 0?
- ¿Qué le falta a tu entorno para que un compañero nuevo pueda clonar el repo y correr el proyecto en menos de 10 minutos?

## ✅ Checklist de Cierre de Sprint 0

- [ ] `entregable-s01-plan-de-trabajo.md` completo
- [ ] Al menos una `feature/*` mergeada a `develop` con CI en verde
- [ ] El commit sigue Conventional Commits
- [ ] El código mergeado es dominio real del proyecto (modelo, entidad, endpoint mínimo) — no un "hello world" vacío
