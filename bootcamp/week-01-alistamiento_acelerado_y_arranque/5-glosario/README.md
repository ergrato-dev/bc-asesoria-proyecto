# 🎓 Glosario — Semana 1

| Término | Definición breve |
|---|---|
| **Informe de diseño** | Anteproyecto, arquitectura, casos de uso e historias de usuario aprobados el trimestre anterior |
| **Backlog** | Lista priorizada de historias de usuario pendientes |
| **Sprint** | Ciclo corto de trabajo con un objetivo concreto — aquí, una semana |
| **Sprint 0** | Primer ciclo, dedicado a dejar el proyecto listo para codificar en serio |
| **Sprint Backlog** | Subconjunto del backlog que el equipo se compromete a completar en el sprint actual |
| **Scrum Master** | Rol que facilita las ceremonias ágiles y remueve bloqueos |
| **Product Owner (PO)** | Rol que prioriza el backlog y valida criterios de aceptación |
| **CODING_STANDARDS.md** | Documento del proyecto real con las reglas de nombrado, formato e indentación acordadas |
| **`develop`** | Rama de integración continua del equipo |
| **`feature/*`** | Rama de una historia de usuario o tarea concreta, creada desde `develop` |
| **Conventional Commits** | Convención de mensajes de commit `tipo(alcance): descripción` |
| **CI (Integración Continua)** | Verificación automática (lint + test) en cada Pull Request |
| **Branch protection** | Regla de GitHub que exige PR + checks antes de mergear a una rama |
| **Docker** | Herramienta de contenerización — empaqueta la app en imágenes reproducibles |
| **Docker Compose** | Herramienta para levantar varios contenedores (backend, frontend, BD) con un solo comando |
| **Dockerfile** | Receta que define cómo construir la imagen de un servicio |
